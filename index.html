Features

What's new for people using the devices: the new Siri, Apple Intelligence across apps, and visionOS's spatial rework.

01 — Platform update

Siri gets rebuilt, and Apple Intelligence gets everywhere

The headline of OS 27 is a new Siri, built on foundation models developed jointly with Google (delayed in the EU and China for regulatory reasons). It's less a feature update than a full replacement of how the assistant understands what's on your screen and what you're trying to do.

Siri AI, the next generation all platforms

Five changes worth knowing, expand each for the specifics:

Dedicated Siri app ›

A standalone hub for every interaction: revisiting past conversations, asking follow-ups, generating text and images, analyzing files, and customizing how Siri sounds and responds.

Spotlight integration ›

On macOS 27, Spotlight becomes a "Search or Ask" interface, with "Ask Siri" surfaced as the top hit by default.

Contextual understanding ›

Siri can read on-screen content, work across apps, and act on what a user is currently looking at, rather than needing an explicit command every time.

Redesigned interface ›

On Dynamic Island iPhones running iOS 27, swiping down from the middle of the screen brings up Siri in a chat-like interface docked at the top.

Siri on the wrist, and everywhere else ›

watchOS 27 gets a dedicated Siri app for full conversations from the wrist. The same upgraded assistant extends into CarPlay and AirPods, and conversations carry over across devices as you move between them.

Apple Intelligence, expanded across apps

Shortcuts

Describe automations in plain language instead of building them block by block.

Safari

Auto-groups tabs by topic, watches pages for changes, and can build a browser extension from a text description.

Passwords

Finds and fixes weak or reused passwords automatically, no manual sign-ins required.

Photos

Better object removal, plus new Extend and Reframe tools; Image Playground's editing model is now more capable and promptable.

Phone

Surfaces relevant info from other apps in the middle of a call.

Liquid Glass

A system-wide transparency slider, better text contrast, and sharper app icons across the board.

02 — Spatial computing

visionOS 27 stops feeling like a beta

Vision Pro gets the most conceptually different update of the cycle: Siri becomes a placeable object in your space, and windows stop being flat.

  • 3D Siri Orb. Siri appears as a placeable orb you can position anywhere in your space. Looking at it is enough to start a conversation, no "Hey Siri" required.
  • Visual awareness. Siri can "see what you see," identifying objects in your surroundings and answering questions about them in real time.
  • Panoramas as environments. Panorama photos convert into immersive spatial environments you can step into, instead of viewing as flat images.
  • Curved app windows. Safari, Freeform, and Apple TV now wrap content around your field of view rather than sitting as flat rectangles.
  • Safari 3D environments. A new immersive API lets developers launch users into full 360-degree environments from inside Safari.
  • Glance-to-expand notifications. Notifications expand automatically when you look at them, cutting down on hand gestures.
  • Spatial Mac preview. Mac owners can preview and edit 3D models directly in visionOS, with Quick Look now supporting annotations on the models themselves.

New developer APIs worth a look: preconfigured held-object tracking, an IR-LED tracked accessories framework, uncovered screen recording, and the immersive Web Environments API for Safari. Details linked below.

Part two

Tech

What's new for building on Apple platforms: the frameworks behind Siri, the Xcode 27 tooling refresh, and everything that changed in Swift 6.3.

03 — Frameworks

The frameworks doing the real work

Foundation Models Framework

Apple's on-device LLM framework got real expansion this cycle.

Image input

A single LanguageModelSession call now reasons over images and text together, instead of text-only.

Server-side routing

The same Swift API can route a request to third-party models, like Claude or Gemini, instead of Apple's own model.

One API, any model

A LanguageModel protocol paired with a LanguageModelExecutor means any provider implementing both plugs into the existing session API. No more maintaining separate SDKs per provider.

Dynamic Profiles

Define multiple model "profiles" in one app, so different agents can handle different sub-tasks instead of one model doing everything.

Small Business Program members under 2 million first-time downloads get free access to Apple's cloud-hosted Foundation Models on Private Cloud Compute.

Core AI Framework

A lower-level sibling to Foundation Models, for developers who want to bring their own model rather than use Apple's. Notably, this is the same framework running Siri AI itself, making it a rare case of Apple exposing its own internal AI infrastructure.

  • Deploy custom LLMs or vision models directly on iPhone and Mac hardware.
  • Ahead-of-time compilation for target hardware, keeping local inference fast.
  • A dedicated Instruments template for profiling where inference time actually goes.
  • Python tooling to convert existing PyTorch models to run on Apple silicon without retraining.

App Intents Framework SiriKit deprecated

App Intents, the framework behind how apps expose actions to Siri, Shortcuts, Spotlight, and Widgets, got a significant refresh. Apple has formally deprecated SiriKit in its favor.

  • ValueRepresentation and RelevantEntities let app content carry structured data across apps, making it more discoverable by Siri.
  • EntityCollection and SyncableEntity improve performance for large entity sets and keep entities synced across a user's devices.
  • Richer parameter types add union values, plus graceful cancellation for intents running longer than 30 seconds.
  • ExecutionTargets gives explicit control over which process (main app, extension, or WidgetKit) handles a given intent.

04 — Tooling

Xcode 27: agents get a real seat at the table

Currently in beta, Apple silicon only, and using around 30% less storage than the previous version.

Coding agents get more capable

Agent conversations now open directly alongside code, and multiple conversations can be organized more easily. The standout addition is Plan mode:

xcode agent prompt
// invoke plan mode before any changes are made
/plan Add a new API call to the profile screen

The agent explores the related code first and proposes which files and changes are needed. You review and refine the plan before asking it to execute. Xcode 27 also ships built-in specialist skills for SwiftUI, accessibility, sizing, testing, and performance, giving agents more context on Apple-platform code specifically.

Untitled Projects

Write, build, and run code without setting up a project, targets, or build settings first, useful for quickly trying an idea or testing an API. Work saves automatically and can later convert into a full Xcode project.

AI-powered localization

Ask an agent to translate an app into a new language and it adds the language, updates String Catalogs, and generates translations using the app's own context. You review and refine the results directly in Xcode.

Themes, expanded

Custom themes now cover the navigator, inspectors, toolbars, and tab bars, with settings synced through iCloud.

Device Hub

Physical devices and simulators live in one place, replacing the standalone Simulator app. Toggle appearance, text size, accessibility, location, and audio conditions on the fly.

Instruments & Organizer

Easier to find and compare performance issues; Organizer adds new post-release metrics and recommendations.

Xcode Cloud

Builds are up to 2x faster, cutting down build-and-test turnaround.

Quality-of-life note: Xcode 27 adds a native "Delete Derived Data" option straight in the Product menu, no more digging through Finder or Terminal.

05 — Language

Swift 6.3: making Swift useful in more places

Swift 6.2 was about making concurrency feel natural. 6.3 is about reach: better C interop, one unified build system taking shape, and an official SDK for Android.

Talking to C got a lot easier

The standout change is @c. Annotating a Swift function or enum with it auto-generates the matching C header declaration:

Swift → generated C header
@c
enum status: CInt { case success, failure }

@c
func callFromC() { ... }

// Generated header
typedef enum { statusSuccess, statusFailure } status;
void callFromC(void);

Pair it with @implementation to write the actual implementation of a function already declared in a C header, directly in Swift. Full detail in SE-0495.

Two modules, same function name, no more headache

Module selector syntax lets you disambiguate identically-named symbols from two imports, without renaming or aliasing anything:

import ModuleA
import ModuleB

let x = ModuleA::getValue()
let y = ModuleB::getValue()
→ resolves to ModuleA.getValue(), no ambiguity error, no import restructuring.

Deeper dive in SE-0491, the module selectors proposal.

For library authors

  • @specialize ships a pre-specialized implementation of a generic function for specific concrete types, so callers get the specialized codepath without the compiler inferring it at each call site.
  • @inline(always) forces inlining at call sites instead of leaving it to the optimizer.
  • @export(implementation), in an ABI-stable library, exposes the actual function body (not just the interface) to clients, unlocking cross-module optimizations previously blocked by the ABI boundary.

Android becomes a first-class target

Swift now has an official, stable SDK for Android. Build native Android binaries, use existing Swift packages on Android, and call Swift directly from Kotlin or Java. This came out of a dedicated Android Workgroup, worth a proper look if you've been eyeing shared code between iOS and Android.

One build system, eventually

Xcode's build system, SPM's native planner, and platform-specific quirks on Linux and Windows have long done things their own way. Swift 6.3 previews Swift Build, a single build engine meant to work consistently across macOS, Linux, and Windows. It's opt-in for now, and the native build system stays default:

terminal
swift build --build-system swiftbuild
swift test --build-system swiftbuild
swift run --build-system swiftbuild MyExecutable

Smaller SPM additions: shared macro libraries can use prebuilt swift-syntax binaries for faster macro-heavy builds; swift package show-traits shows a package's supported traits without digging through its manifest; doc generation plugins now give more control over pulling in inherited docs.

Embedded Swift and WebAssembly, steadier

A batch of Embedded Swift fixes that had sat in nightly builds for months finally landed officially, including description and debugDescription support for floating point types, smoother C interop, and a new opt-in EmbeddedRestrictions warning group that catches unsupported code before the build fails. WebAssembly support, official since 6.2, gets continued toolchain fixes, better JS interop, improved WasmKit debugging, and an Embedded Swift variant of the Wasm SDK for smaller binaries.
